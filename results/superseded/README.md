# Superseded E3 results

The files in this directory were produced under an **incorrect explicit-Euler step
rule** and are retained only so that the record of what changed is auditable. Nothing
in the manuscript is derived from them.

## What was wrong

The forward pass limited the explicit step by

    tau <= 0.9 * 2 / r,        r = max_i sum_j |D_ij|

which accounts for the diffusion factor of the splitting step but not for the source
factor. The step has amplification

    (1 - tau*beta) * (1 - tau*lambda)

on the eigenmode `lambda` of `L`, so both factors must have modulus at most one. With
the Gershgorin bound `lambda_max(L) <= 2r` and the shift guarantee
`beta >= |lambda_min(L)|`, the correct limit is

    tau <= 0.9 * min(1/r, 1/beta).

The omitted `1/beta` argument is the one the source term imposes. It is inactive when
`beta` is small, which is the positive-definite case, and binding when `beta` is large,
which is the indefinite (Lorentzian) case. On a normalised operator (`r = 1`) the old
rule permits `tau = 1.8`; with the measured `beta` of the indefinite variant, which lies
between 2.12 and 2.60, the amplification then reaches 13.6 to 20.9 — far outside the
stability region. The corrected rule keeps every run inside it: the re-run reports
`worst_amplification = 0.9582` and `n_unstable = 0`.

Both were run with `deterministic = strict` and the step rule
`tau <= 0.9 * min(1/r, 1/beta)`, as their `e3_cfl_summary_*.json` sidecars record.

## Two further consequences

1. `code_version` in the notebook is now `tsipn-v4-corrected-cfl-det-kmax64`. Because
   `CONFIG_HASH` is a sha1 of the configuration dataclass, the bump changes `PREFIX`
   and therefore every output filename. No result cached under the old step rule can be
   silently reused — which is why the bump matters and not only the code change.
   The cost is that a fresh run repeats the whole grid, not only E3.

2. Any `REPORT.md` carrying the pooled delivered horizons
   `euler [1.0, 2.0, 4.0, 7.94, 15.39, 29.4]` was generated from the superseded pass.
   The corrected pass gives `euler [0.84, 1.59, 2.81, 4.86, 9.04, 14.79]` for the same
   pooled view. `REPORT.md` is regenerated by the notebook, so a fresh run replaces it.

The experiments other than E3 are unaffected: they run with `propagator = "exact"`, so
the explicit step rule never enters them. Their files keep the `MAIN_ae15dbc3` prefix
and remain the data the manuscript reports for E1, E2, E4 and E5.
